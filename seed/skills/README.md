# Skills 库（可复用技能）

> 把「可复用、已验证」的操作序列沉淀为 skill：Markdown 指令 + 脚本 + 验收标准。
> 每个 skill 由周复盘（`weekly_review.py`）或人工识别后创建，随使用迭代版本化。

## 目录约定

```
skills/
├── README.md              # 本文件
├── _template.md           # 新建 skill 的模板
└── <skill-name>.md        # 每个 skill 一个文件
```

## 一个 skill 包含什么

见 `_template.md`，核心字段：`id / 名称 / 触发条件 / 依赖 / 状态 / 目标 / 步骤 / 脚本 / 验收标准 / 效果评分`。

## 从 run-log 演进 skills 的闭环

```
应用里的操作（转换/归档/提示词重写）
        │  自动留痕，无需手动记
        ▼
  logs/run-log.jsonl（成果 + 过程）
        │  SkillsService.propose() 提炼
        ▼
  「本期可沉淀」——应用「运行日志与复盘」页
        │  点「采纳」
        ▼
  skills/<id>.md 草稿（触发条件与证据已预填，解法待补）
        │  用一次点「记一次」
        ▼
  uses / last_used 累积 → 长期闲置会被提醒归档
```

> **2026-08-20 起这条链是自动的**。此前 `logs/run-log.jsonl` 一直是空的，
> 因为记录靠手动敲命令；现在应用自己的格式转换、git 归档、提示词重写都会自动留痕，
> 复盘时就有真实数据可算。

## 判定规则（已实现为可测试的代码）

提炼规则见 `apple/LifeWorkflowKit/Sources/LifeWorkflowKit/Services/SkillsService.swift`：

| 信号 | 阈值 | 产出 |
|------|------|------|
| 同一错误重复出现，且现有 skill 未覆盖 | ≥ 2 次 | **沉淀避坑** —— 生成草稿，预填错误与触发条件 |
| 同一工具组合连续**成功**配合 | ≥ 3 次 | **固化流程** —— 生成草稿，附上实际成功过的场景 |
| 现有 skill 已覆盖该错误，但坑仍复发 | ≥ 2 次 | **对策未生效** —— 提醒去改 skill，不重复新建 |
| 已验证的 skill 长期未被使用 | ≥ 90 天 | **长期闲置** —— 提醒归档，或你只是忘了它 |

阈值背后的判断：错误只出现一次可能是偶然，不值得沉淀；失败的运行不计入流程固化，
只固化真的成功过的组合。

## 手动判定（自动规则之外）

- 被多次执行、步骤固定的操作（如格式转换、日志记录、提示词重写）。
- 有明确输入/输出与可验证结果。
- 失败过一次、已找到稳定解法（把坑写进 skill 的「注意」）。
