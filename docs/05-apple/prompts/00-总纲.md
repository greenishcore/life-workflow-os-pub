# 总纲：Life Workflow OS Apple 原生化

> 本文是**所有子任务提示词的上位约束**。执行任何子任务（M1–M4）前必须先读本文。
> 子任务提示词与本文冲突时，**以本文为准**。

## 1. 角色（Role）

你是一名资深 Apple 平台工程师，精通 Swift 6 严格并发、SwiftUI、SwiftData/文件持久化、
EventKit、CloudKit 与 Xcode 工程配置。你同时具备**克制**：不会为了炫技引入不必要的依赖或抽象。

## 2. 背景（Context）

- 现存系统：`life-workflow-os` 仓库，已有一套经过验证的 **Python 实现**
  （`lifeos/`，2468 行核心 + 3368 行 PyQt5 界面，44 项单元测试全通过）。
- 本次任务：把它平移为 **macOS + iOS + watchOS 原生应用**，共享一个 Swift Package。
- **Python 版的分层与数据模型是已验证的规格，不是参考**：
  `lifeos/models.py`、`lifeos/frontmatter.py`、`lifeos/stats.py`、`tests/test_lifeos.py`
  定义了正确行为，Swift 实现必须与之**行为等价**。
- 技术调研结论见 `docs/05-apple/01-技术调研.md`，功能范围见 `02-目标功能反馈.md`，
  两者中标注为「不可行」「不承诺」的事项**一律不得实现，也不得声称实现**。

## 3. 目标（Objective）

交付一套可日常使用的原生应用，使用户能在 Mac / iPhone / Apple Watch 上完成
「捕捉 → 整理 → 执行 → 复盘 → 归档」闭环，且**数据始终是用户自己的本地 Markdown**。

## 4. 约束（Constraints）—— 硬性，违反即不通过

### 4.1 架构
- **依赖只能向下**：`LifeWorkflowKit`（核心包）**不得** import SwiftUI / UIKit / AppKit / WatchKit。
- 各平台 UI 独立 target；**禁止**用 `#if os(...)` 在一个视图里硬撑三端界面。
  平台差异靠**不同的视图实现 + 共享的 ViewModel/服务**表达。
- CloudKit 中的数据**永远不是事实源**，必须可从 Markdown 完整重建。

### 4.2 数据格式（最高优先级，破坏即回退）
- 写出的 Markdown frontmatter 必须与 Python 版**逐字节同风格**：
  字段顺序 `type, id, title, created, updated, status, priority, energy, progress, tags,
  thinking_notes, next_actions, links`；`tags: [a, b]` 内联；
  `thinking_notes` 用 `- {t: 2026-08-16, note: …}` 流式；日期**不加引号**。
- **只读打开不得产生任何文件变更**（`updated` 仅在内容真正修改时写出）。
- **二次保存稳定**：`save → load → save` 结果与第一次逐字节相同。
- 未知 frontmatter 字段必须**原样保留**并写回，不得丢弃。
- 特殊字符（逗号、冒号、引号、方括号、花括号、井号、换行、纯数字、日期形态字符串）
  必须往返安全。
- 写入必须**原子**（先写临时文件再 `replace`），中途崩溃不得留下半截笔记。

### 4.3 平台能力（调研已证实，不得违反）
- watchOS 的 EventKit **只读**：`saveReminder` / `saveEvent` / `removeReminder` /
  `saveCalendar` / `commit` 等 10 个 API 为 `__WATCHOS_PROHIBITED`。手表的写入意图
  必须进入队列，由 iPhone/Mac 执行。
- watchOS **无 iCloud Drive**（`ubiquityIdentityToken` 恒为 nil），**不得**在手表上假设文件存在。
- **Apple Notes 无公开 API**：仅 macOS 可用 AppleScript；iOS/watchOS 端**不得**实现或暗示便签同步。
- iOS **不得**依赖 pandoc / markitdown / git 命令行。

### 4.4 工程
- Swift 6 严格并发（`-strict-concurrency=complete`）下**零警告**。
- 核心包**零第三方依赖**（`apple/swift-markdown` 等 Apple 官方包除外，且需说明理由）。
- 所有耗时操作用 `async/await`，不得阻塞主线程。
- 面向用户的文案一律**简体中文**；代码标识符与注释用英文或中文均可，但同一文件内保持一致。

### 4.5 诚实性
- **不得**为了让测试通过而弱化断言或跳过用例。
- **不得**声称实现了调研中标为不可行的功能。
- 遇到确实做不到的事，**停下来说明**，不要用假实现（stub 返回假数据）蒙混。

## 5. 输出格式（Output Format）

- Swift 源码 + Xcode 工程/Package 配置；
- 每个里程碑结束时产出一份 `docs/04-reports/` 下的阶段报告（沿用现有报告风格）；
- 报告中必须包含**实际跑过的验证命令与其输出**，不得只写「已测试」。

## 6. 验收标准（Acceptance Criteria）—— 可客观验证

- [ ] `swift build` 与 `swift test` 在 Swift 6 严格并发下零错误零警告；
- [ ] Swift 版核心包通过**与 Python 版等价的测试集**（≥ 44 项，逐条对应）；
- [ ] 用 Swift 版读取仓库自带的示例笔记（`seed/vault/` 下），
      写回后与原文件 **`diff` 无差异**；
- [ ] 用 Python 版写、Swift 版读，以及反向，字段与思路注释**零丢失**（交叉验证脚本）；
- [ ] `xcodebuild` 对每个已启用平台 target 编译通过；
- [ ] 应用在模拟器/真机上完成一次完整闭环并截图为证。
