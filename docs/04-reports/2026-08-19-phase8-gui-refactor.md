# Phase 8 阶段报告：重构为分层架构，交付桌面应用

日期：2026-08-19 · 版本：v1.0.0 · 覆盖：架构重构 + GUI 产品化

## 一、这一期解决的问题

Phase 0–7 把「捕捉 → 整理 → 执行 → 复盘 → 归档」的**能力**全部跑通了，
但交付形态是 10 个互不相识的脚本 + 11 个 Obsidian 插件。带来三个实际后果：

1. **摩擦高**：要用得记住十来条命令与各自的参数，隔一周自己都想不起来；
2. **改不动**：业务逻辑与 argparse/echo 焊死，想做界面等于全部重写；
3. **看板名不副实**：静态 HTML 只读、依赖 CDN，「想法是一等公民」在数据模型上成立，
   在使用上不成立——改个状态、补条思路注释都得手编 YAML。

本期不推翻 v1 的信息流闭环（那个是对的），而是**给它一个软件形态**。

## 二、做了什么

### 1. 抽出 UI 无关的核心包 `lifeos/`（2468 行）

```
基础层  config.py（单一配置源） · services/proc.py（子进程统一封装）
数据层  models.py（Item/ThinkingNote/RunLog/状态机） · frontmatter.py（确定性序列化）
        repository.py（扫描/索引/CRUD/原子写/回收站）
服务层  convert · prompts · runlog · review · apple · archive · stats
```

强约束：**依赖只能向下，服务层不 import 任何 PyQt5。**
同一份逻辑现在同时支撑 GUI、CLI、CI 三个消费方。

### 2. PyQt5 桌面应用（3368 行）

8 个页面按五阶段闭环组织；明暗双主题；图表用 `QPainter` 原生绘制，
零外部资源、离线可用、主题切换即时生效。

| 页面 | 关键改进 |
|------|---------|
| 看板 | 融合时间轴：每条想法是一条**生命线**（起点=产生日，沿线刻度=思路演进），不再是孤点 |
| 快速捕获 | 补上 **Inbox → 想法** 的断口：随手记一键提升为带状态机的想法 |
| 想法库 | 五维度全部可编辑 + 思路注释时间轴（可增删），**从只读变可写** |
| 格式转换 | 支持拖拽；缓存命中与否明确告知 |
| 提示词工作台 | 生成、编辑、留档一体 |
| 日志与复盘 | 统计可视化 + 一键生成周复盘 |
| 版本归档 | git 状态/提交/推送/里程碑 release 全在界面里 |
| 设置 | vault 切换、依赖体检 |

### 3. 三个具体缺陷的修复

| 缺陷 | 修法 |
|------|------|
| 看板依赖 ECharts CDN，断网即空白 | GUI 用 QPainter；HTML 版改为**服务端生成的内联 SVG**，全文件零 `http` |
| 保存笔记产生噪音 diff | 自写确定性 YAML 发射器：字段定序、日期不加引号、`updated` 只在真正修改时写出 |
| 中文文件名在 git 状态里显示成八进制转义 | `git -c core.quotepath=false status` |

### 4. 向后兼容

`scripts/` 下的老命令全部改写为**薄壳**转调 `lifeos.cli`：
参数、输出、退出码不变，既有的 GitHub Actions、launchd、Makefile **零改动**。
已实测 `capture.sh` / `convert.sh` / `dashboard.py` / `log_run.py` /
`rewrite_prompt.py` / `weekly_review.py` / `sync.sh` / `release.sh` 全部照常工作。

### 5. 打包为 macOS 应用

`tools/build_app.sh` → `dist/Life Workflow OS.app`，带自绘图标（五阶段闭环节点）
与 AppleScript 自动化权限声明。启动器型包：`git pull` 后立即是新版本。

## 四、指标

| | 重构前 | 重构后 |
|---|---|---|
| 入口 | 10 个脚本 + Makefile + 11 个插件 | 1 个应用（+ 保留全部老命令） |
| 业务逻辑实现份数 | 每个脚本各一份 | 1 份（`lifeos/`），三个消费方共用 |
| 看板 | 只读、依赖 CDN | 可交互可编辑、零外部依赖 |
| 想法编辑 | 手编 YAML | 界面控件 |
| Obsidian | 必需（11 插件） | 可选 |
| 自动化测试 | 0 | 44 单测 + GUI 冒烟 + CI |
| 配置来源 | 每脚本各读各的环境变量 | 单一配置源，优先级明确 |

## 五、明确没做的事

- 不引入数据库：Markdown 仍是唯一事实源；
- 不做云同步：归档仍走 git/GitHub；
- 不做移动端：手机看自包含 HTML 看板（Actions 自动生成）；
- `.app` 是启动器型包，移动仓库后需重新打包。
