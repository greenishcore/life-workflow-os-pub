### 几个具体决定

**xcodegen 而非手写 .xcodeproj**：只把 `project.yml` 入库，工程文件可重建。
避免 `.xcodeproj` 这种二进制式 XML 在版本控制里制造合并冲突，同时保留
「在 Xcode 里打开配签名、加 iOS target」的能力。

**ProcessRunner 显式查找可执行文件路径**：GUI 应用继承的 PATH 很窄，
不显式在 `/opt/homebrew/bin` 等位置找，pandoc / gh 这类 Homebrew 工具会
「明明装了却报找不到」。

**git 仓库靠向上搜索 `.git` 定位**，而不是用 `#filePath` 推算。
后者是编译期常量，应用一旦被移动或换台机器构建就指向不存在的路径——
这个 bug 在第一版里真实存在，被快照发现后改掉并补了测试。

### 2.1 离屏快照工具

macOS 应用没有 iOS 模拟器那样的无头截图能力，而 `screencapture` + AppleScript
取窗口位置会触发「自动化」权限弹窗——在自动化验证与 CI 里都会把进程卡死
（这个坑本期踩过两次）。因此给应用加了 `--snapshot <dir> --vault <path>` 模式，
用 `ImageRenderer` 直接渲染视图树，不需要任何权限。

**它能验证什么**：整体布局、AppState 数据绑定、Swift Charts 图表、明暗主题、
自绘组件（热力图、进度环、思路注释时间轴）。

**它验证不了什么**（如实说明，不拿截图当完整证据）：
1. `TextField` / `Picker` / `Slider` 等 AppKit 支撑的控件，ImageRenderer 无法
   栅格化，截图里显示为黄色占位块；真实运行时是正常原生控件。
2. `NavigationSplitView` / `HSplitView` 同理，快照里换成等价的 HStack 布局。
3. `.task` 修饰符不会被执行，所以靠它加载数据的页面（归档、日志、捕获列表）
   在截图里停留在初始空状态。

因此「八个页面均可交互」这一条由**构建通过 + 应用实际启动运行 + 服务层 64 项
测试**共同支撑，而不是仅靠截图。

## 四、怎么用

```bash
cd apple/LifeOSApp
xcodegen generate                       # 首次或改了 project.yml 后
xcodebuild -scheme LifeOS-macOS build   # 或直接 open LifeOS.xcodeproj 在 Xcode 里跑
open ~/Library/Developer/Xcode/DerivedData/LifeOS-*/Build/Products/Debug/"Life Workflow OS.app"
```

当前用 ad-hoc 签名（`CODE_SIGN_IDENTITY: "-"`），本机运行没问题。
配了 Apple ID 后把 `project.yml` 里的签名设置改成 Automatic 即可分发。
