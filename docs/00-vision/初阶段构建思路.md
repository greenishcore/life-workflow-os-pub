# 初阶段构建思路（原始构想存档）

> 本文档存档项目**最初的完整构想**，作为后续所有阶段的上位依据。
> 记录日期：2026-08-19 · 状态：已在 Phase 0–8 中部分实现，现进入 Apple 生态原生阶段。

## 一、原始表述（逐字存档）

> 这个项目主要是改造我的生活工作流：
>
> 1. 首先是**文字记录、进度管理**（包含每天的想法点子），能有**注释显示我的思路**，
>    最好有**新颖的可视化看板**，能融合时间等各要素。
> 2. 其次是**和各个平台的数据链路打通**，如 Apple 的便签、日程、日历、提醒，
>    融入例如 Obsidian 这种**构建本地知识库**，将 PDF、Markdown 这种文字格式
>    **互转固化路径以节省算力**。
> 3. 然后是**梳理信息流**，将 **skills 演进**逐渐完善，如每次进行 agent 操作都
>    将**成果以及过程清晰记录的日志系统**以供后期复盘。
> 4. 还有每次 agent 交互前都先将**自然语言先重写润色构建新提示词文档**，
>    再根据提示词进行执行。
> 5. 可人的**阶段性成果推送至 GitHub** 上做好版本控制以及归档。
>
> 以上只是几种思路，**先检索再做整合逻辑化，再做规划，形成阶段性报告并输出**。

## 二、拆解为五条主线

| # | 主线 | 内涵 | 成败判据 |
|---|------|------|----------|
| 1 | **记录与进度** | 想法/点子是一等公民，带**思路注释**（思维轨迹）；融合时间的可视化看板 | 看板能回答「这个想法何时产生、如何演进、现在到哪一步」 |
| 2 | **数据链路** | Apple 便签/日历/提醒 ↔ 本地 Markdown ↔ Obsidian | 一键把当日 Apple 数据汇入知识库，不用手抄 |
| 3 | **格式固化** | PDF/Markdown/Word 互转收敛为**唯一 pipeline + 缓存** | 同一文件二次转换命中缓存、秒级返回 |
| 4 | **信息流与 skills** | agent 每次操作留痕（成果 + 过程），复盘提炼可复用 skills | 任意一次交互可追溯「提示词 → 过程 → 产出 → 复盘」 |
| 5 | **提示词前置** | 交互前先把口语重写为结构化提示词文档，再执行 | 提示词文档纳入版本控制，可追溯每次到底让 agent 做了什么 |
| 6 | **归档** | 阶段成果 commit/tag/release 到 GitHub | 笔记与文档改动自动进入版本历史，里程碑可回溯 |

## 三、贯穿始终的方法论（用户明确要求）

> **先检索 → 再整合逻辑化 → 再规划 → 形成阶段性报告并输出**

这条方法论本身就是项目的一部分：不拍脑袋，每个阶段先调研真实可用的工具与链路，
再做架构整合，再排路线图，最后产出可归档的阶段报告。
`docs/01-research/` → `docs/02-architecture/` → `docs/03-roadmap/` → `docs/04-reports/`
的目录结构即由此而来。

## 四、贯穿始终的设计原则

1. **本地优先（Local-first）**：数据以纯文本 Markdown 落盘，不锁死在任何 SaaS。
2. **可版本化**：一切文档与脚本纳入 Git，阶段性成果打 tag/release。
3. **可复盘**：agent 的每次操作都留痕（输入提示词、过程、产出、耗时、错误）。
4. **算力经济**：格式转换固化为可复用、可缓存的 pipeline，避免重复计算。
5. **降级而非崩溃**：缺依赖只让对应功能降级，并明确告知缺什么。
