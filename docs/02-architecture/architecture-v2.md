# 架构 v2 —— 从「脚本集合」重构为「分层软件」

> v1（`architecture.md`）定义了**信息流闭环**：捕捉 → 整理 → 执行 → 复盘 → 归档。
> 那个闭环是对的，本次重构不推翻它，而是给它一个**软件形态**。
> 本文只讲变了什么、为什么变、以及新的分层契约。

## 1. 重构前的实际问题

v1 的能力全部散落在 10 个脚本里，跑起来是通的，但作为「一个东西」是不成立的：

| 问题 | 具体表现 | 后果 |
|------|----------|------|
| **没有统一入口** | 要记 `capture.sh` / `convert.sh` / `dashboard.py` / `log_run.py` / `rewrite_prompt.py` / `weekly_review.py` / `sync.sh` / `release.sh` + Makefile + 11 个 Obsidian 插件 | 摩擦高到只有作者本人能用；隔一周自己也想不起来 |
| **逻辑不可复用** | 业务逻辑与 `argparse`/`echo`/文件 IO 焊死在脚本里 | 想做界面 = 全部重写一遍 |
| **看板只读** | `dashboard.py` 生成静态 HTML，改状态、加思路注释只能手编 YAML | 「想法是一等公民」在数据模型上成立，在使用上不成立 |
| **看板离线即废** | HTML 依赖 ECharts CDN | 断网 / CDN 抖动 = 看板空白 |
| **解析逻辑重复且脆弱** | frontmatter 解析在 `dashboard.py` 里一份，别处各写各的；无校验、无归一化 | 字段拼写错、日期格式不一致时静默丢数据 |
| **核心体验被插件绑架** | 看板/任务/查询依赖 Templater+Dataview+Kanban+Tasks+… | SETUP 有 11 个插件要装，换台机器重来一遍 |
| **配置各行其是** | 每个脚本自己读 `VAULT_DIR`/`LOG_DIR`，默认值各写一遍 | 「命令行改的」和「另一个脚本看到的」可能不是同一个 vault |

一句话：**v1 是一套能跑的自动化脚本，不是一个软件。**

## 2. 重构后的分层

```
┌──────────────────────────────────────────────────────────────────┐
│  表现层  lifeos/gui/            PyQt5 桌面应用（8 个页面）            │
│          lifeos/cli.py          命令行（10 个子命令）                 │
│          lifeos/html_dashboard  自包含 HTML 看板（CI / 手机查看）      │
│          scripts/*              兼容壳（老命令一字不改照常能用）        │
├──────────────────────────────────────────────────────────────────┤
│  服务层  lifeos/services/       capture · convert · prompts        │
│                                 runlog · review · apple · archive  │
│          lifeos/stats.py        看板聚合（纯函数）                    │
├──────────────────────────────────────────────────────────────────┤
│  数据层  lifeos/repository.py   vault 扫描 / 索引 / CRUD / 原子写      │
│          lifeos/models.py       Item · ThinkingNote · RunLog · 状态机 │
│          lifeos/frontmatter.py  确定性序列化（读写往返保真）            │
├──────────────────────────────────────────────────────────────────┤
│  基础层  lifeos/config.py       单一配置源（GUI 与 CLI 共用）          │
│          lifeos/services/proc   子进程统一封装（超时/编码/日志回调）     │
├──────────────────────────────────────────────────────────────────┤
│  存储    本地 Markdown + frontmatter（唯一事实源，不变）               │
└──────────────────────────────────────────────────────────────────┘
```

**唯一的强约束：依赖只能向下。** 服务层不 import 任何 PyQt5，数据层不知道服务层存在。
这条约束的直接收益是：同一份逻辑同时支撑 GUI、CLI、CI 三个消费方，永远不会跑偏。

### 各层职责

| 层 | 不变量 |
|----|--------|
| 基础 | 路径与偏好只有一个来源；优先级 **环境变量 > `~/.config/lifeos/config.json` > 仓库默认值** |
| 数据 | 所有对 vault 的读写都过 `VaultRepository`；写入必须原子；序列化必须确定性 |
| 服务 | 每个服务是纯函数或无状态对象，接收 `config`，返回结果对象，用 `log` 回调汇报进度——不 print、不退出进程 |
| 表现 | 只做编排与呈现；任何可能阻塞的调用必须走 `TaskRunner` 后台线程 |

## 3. 关键设计决定

### 3.1 为什么是 PyQt5 而不是 Electron / Web
- 机器上**已装** PyQt5 5.15.2 + PyYAML，零新增依赖；
- 本地优先的工具不该为了画界面拉进一个浏览器内核；
- 图表用 `QPainter` 原生绘制 → 彻底摆脱 CDN，离线可用，主题切换即时生效。

### 3.2 确定性序列化（`frontmatter.py`）
不用 `yaml.dump`，自己写发射器。理由有三条，缺一不可：
1. **字段顺序固定** —— 否则每次保存都产生噪音 diff，git 历史被污染；
2. **与手写笔记逐字节同风格**（`tags: [a, b]`、`- {t: 2026-08-16, note: …}`）—— 保证 Obsidian、Dataview 与人眼三方都认；
3. `yaml.dump` 会转义中文、重排键、给日期加引号，可读性与兼容性都掉。

配套两条不变量，均有测试守护：
- **只读打开不产生变更**：`updated` 只在 `touch()` 时写出，浏览不留痕；
- **二次保存稳定**：`save → load → save` 的结果与第一次逐字节相同。

### 3.3 把「思维轨迹」从数据字段变成可视对象
v1 里 `thinking_notes` 只是 frontmatter 的一个 list，看板把它平铺成表格文字。
v2 里它有了两个专属呈现：
- **想法编辑器**中的时间轴（左侧竖线 + 节点 + 日期），可直接增删；
- **融合时间轴**上每条想法是一条**生命线**：起点=产生日，沿线刻度=每次思路演进，终点=最后一次更新。

这才真正回答了路线图 Phase 5 的验收标准——「这个想法何时产生、如何演进、现在到哪一步」。

### 3.4 补上 Inbox → 想法 的断口
v1 捕捉完就躺在 `Inbox/*.md` 里，没有通往想法库的路，只能手工复制粘贴再补 frontmatter。
v2 在捕捉页给每行随手记加了「→ 想法」：一键生成带状态机与首条思路注释的 Idea，并把原行标记为已处理。

### 3.5 Obsidian 从「必需」降级为「可选」
看板、编辑、查询、任务现在都由应用自己提供。Obsidian 仍然可以打开同一个 vault
（数据格式完全兼容），但**不装也能用全部功能**。SETUP 的 11 个插件从必装变成推荐。

### 3.6 老命令一律保留
`scripts/` 下的脚本全部改写为薄壳，转调 `lifeos.cli`：
参数、输出、退出码保持原样，GitHub Actions / launchd / Makefile 无需改动，
但逻辑只有一份实现。

## 4. 数据模型（相对 v1 的变化）

模型本身**不变**（见 `data-model.md`），只是从「约定」变成了**被代码强制的类型**：

| v1 | v2 |
|----|----|
| `status` 是 frontmatter 里的字符串，靠自觉 | `Status` 枚举，带 `label`/`color`/`next()`，非法值归一为 `seed` |
| `priority` 同上 | `Priority` 枚举，带展示权重（散点图点径） |
| `energy` / `progress` 可能超界 | 读取时钳制到 `0–10` / `0–100` |
| `thinking_notes` 是裸 dict list | `ThinkingNote` 数据类，日期自动归一化 |
| 未知字段可能被工具丢弃 | 一律保留并原样写回 |

## 5. 并发与失败处理

- 所有耗时操作（转换、git push、AppleScript、调 LLM）走 `TaskRunner`（QThread），界面不冻结；
- 子进程统一经 `services/proc.py`：带超时、统一编码、错误不抛异常而是返回 `Result`，由调用方决定怎么展示；
- AppleScript 权限被拒时给出**具体的系统设置路径**，而不是一句「失败」；
- 依赖缺失（如没装 xelatex）只让对应功能降级（回退 Chrome 渲染 PDF），不影响其它模块。


## 7. 没有做的事（明确的边界）

- **没有引入数据库**：Markdown 仍是唯一事实源，vault 换台机器复制就能用；
- **没有做云同步**：归档仍走 git/GitHub，符合本地优先原则；
- **没有做移动端**：手机上看用自包含 HTML 看板（GitHub Actions 自动生成）；
- **`.app` 是启动器型包**：代码与数据仍在仓库，`git pull` 即更新；若移动仓库位置需重新运行 `tools/build_app.sh`。
